# C2ATrace v0.1 — Phase 1 Part B: Transform / Derivation Semantics

Status: ACCEPTED AFTER ADVERSARIAL REVIEW.

Scope: Transform use/generation/selection semantics; one-to-one, one-to-many, and many-to-one lineage; exact, partial, and unknown derivation; region mapping; operation semantics for extract, split, chunk, filter, rerank, truncate, concat, template, normalize, and redact; control-flow influence without output-content contribution.

JSON Schema: NOT FROZEN.

Implementation: NOT STARTED.

## 1. Design objective

Part B defines how C2ATrace records representation lineage after a source has been observed.

The central separation is:

~~~text
Transform used Artifact A
+
Transform generated Artifact B
≠
B is automatically derived from A
~~~

A Transform records an Activity.

A Derivation records a positive ancestry Assertion.

A usage can affect selection, ordering, branching, thresholds, or other control flow without contributing representation content to a generated output.

C2ATrace therefore separates:

~~~text
use
generation
selection/forwarding
derivation
control influence
~~~

## 2. Transform semantics

### 2.1 Transform identity

A Transform is an Activity representing one recorded transformation step.

A Transform can:

- use zero or more Artifacts;
- generate zero or more new Artifacts;
- select or forward zero or more existing Artifacts;
- carry descriptive implementation/operation metadata.

Transform identity represents the recorded activity occurrence, not a reusable algorithm identity.

Two executions of the same implementation are distinct Transform activities when they are distinct recorded occurrences.

### 2.2 Generation

Generation means that a Transform created a new Artifact identity representing a new recorded representation.

Generation does not establish which used inputs contributed representation content.

### 2.3 Selection / forwarding

Selection or forwarding means that a Transform chose an already-existing Artifact for downstream use without claiming that the Transform created that Artifact.

This distinction is required for operations such as:

~~~text
filter candidates
rerank chunks
choose top-k
route one branch
pass through an unchanged artifact
~~~

A selected Artifact retains its existing identity.

If an implementation creates a new wrapper, list, manifest, or reordered aggregate representation, that new representation is a generated Artifact distinct from the selected member Artifacts.

### 2.4 Usage role

A Transform input use can carry a Producer-asserted usage role.

Part B defines the conceptual roles:

~~~text
data
control
mixed
unknown
~~~

**data**

The Artifact is used as data that may contribute representation content. This role alone does not establish that contribution occurred.

**control**

The Producer asserts that the Artifact affected selection, ordering, branching, thresholds, parameters, or another control decision but did not contribute representation content to the generated output representation(s).

**mixed**

The input was used both as potential/contributing representation data and for control decisions.

**unknown**

The Producer cannot establish the role more precisely.

Usage role is not Derivation.

A positive content-contribution claim requires a Derivation Assertion.

## 3. Derivation as a qualified n-ary Assertion

### 3.1 Why binary edges are insufficient

The Phase 0 diagram showed binary shorthand:

~~~text
output derived_from input
~~~

Part B refines the normative semantics.

A Derivation Assertion has:

- exactly one target output Artifact or output Region;
- exactly one generating Transform;
- one or more contributing input Artifacts or input Regions;
- a derivation precision;
- optional mapping/evidence metadata.

This n-ary form preserves joint contribution for many-to-one transforms.

A binary derived_from edge is only shorthand for a Derivation Assertion with one contributing input.

### 3.2 Direct derivation

A Part B Derivation Assertion describes direct derivation through one Transform.

Its output is generated by that Transform.

Its contributing inputs are inputs used by that Transform.

Longer ancestry across multiple Transforms is lineage reachability, not a single direct Derivation Assertion.

### 3.3 Exact derivation

An **exact derivation** is a positive direct Derivation Assertion whose claimed output scope has complete recorded origin accounting at the asserted granularity.

For the claimed output scope:

1. all contributing input scopes are explicitly identified;
2. their relevant input-to-output mapping is explicit at the declared Region granularity;
3. any output region not derived from an input is explicitly accounted for as transform-generated content;
4. no unknown representation-content contributor is asserted to remain for that output scope.

Exact does **not** mean:

- byte equality;
- reversibility;
- semantic equivalence;
- causal responsibility;
- external truth of the Producer's instrumentation.

Normalization, redaction, or other content-changing transforms can still have exact recorded derivation when ancestry and region accounting are complete.

### 3.4 Partial derivation

A **partial derivation** is a positive direct Derivation Assertion that establishes some recorded representation ancestry but does not completely account for the claimed output scope.

Examples include:

- known contributor but unknown exact input Region;
- known input Region but unknown output Region;
- known contribution from one input while other content contributors remain unknown;
- privacy-preserving lineage that intentionally omits fine-grained mappings;
- a parser/extractor that records source ancestry without exact source-position mapping.

Partial means positive ancestry is asserted.

It does not mean "possibly derived."

### 3.5 Unknown derivation

**Unknown derivation** is a state of knowledge, not a positive Derivation Assertion.

If a Transform used an Artifact but the Producer cannot justify whether that Artifact contributed representation content to a generated output, the Producer records the use with role unknown (or another justified non-derivation usage role) and does not manufacture a positive Derivation Assertion.

Thus:

~~~text
unknown derivation
≠
partial derivation
~~~

Partial says:

> some contribution is known.

Unknown says:

> contribution cannot be established.

## 4. Transform topology

### 4.1 One-to-one

~~~text
A
↓ use
Transform T
↓ generate
B
~~~

A direct Derivation Assertion can relate B to A if contribution is known.

Examples:

- normalize one text artifact;
- redact one document;
- extract one field representation;
- truncate one artifact.

### 4.2 One-to-many

~~~text
       ┌→ B1
A → T ─┼→ B2
       └→ B3
~~~

Each generated output has its own direct Derivation Assertion or derivation-knowledge state.

The existence of derivation for B1 does not imply derivation for B2 or B3.

Examples:

- split;
- chunk;
- extraction of multiple outputs.

### 4.3 Many-to-one

~~~text
A ─┐
B ─┼→ T → O
C ─┘
~~~

A Derivation Assertion targeting O can identify one or more contributing inputs jointly.

Not every used input has to be a representation contributor.

Examples:

- concat;
- template interpolation;
- merge;
- structured assembly.

### 4.4 Many-to-many

Many-to-many is represented as one Transform with multiple generated outputs and separate target-specific Derivation Assertions.

Core v0.1 does not need a single Derivation Assertion with multiple output targets.

This keeps precision and region coverage local to one target output.

## 5. Region semantics

### 5.1 Region

A Region identifies a subrepresentation of an immutable Artifact.

A Region is meaningful only relative to:

- one Artifact identity;
- one representation basis;
- one selector/coordinate scheme.

Examples of future selector schemes may include:

~~~text
byte interval
Unicode-scalar interval
structured path
array/member selector
media segment selector
other profile-defined selector
~~~

Part B does not freeze those selector vocabularies.

### 5.2 Input-to-output mapping

A Derivation Assertion can map:

~~~text
input Artifact + input Region
→
output Artifact + output Region
~~~

or multiple input Regions jointly into one output Region.

Mappings can overlap.

One input Region can map to multiple output Regions.

Multiple input Regions can map to one output Region.

### 5.3 Representation-basis discipline

Range/Region coordinates cannot be interpreted independently of their representation basis.

For example:

~~~text
UTF-8 byte offsets
≠
Unicode scalar offsets
≠
normalized-text offsets
~~~

A verifier cannot silently translate between coordinate systems unless an applicable profile defines the translation.

### 5.4 Whole-artifact shorthand

When a Derivation Assertion omits a Region at one endpoint under a profile that permits omission, that endpoint refers to the entire declared Artifact representation.

The exact wire representation of whole-artifact scope is deferred.

## 6. Output-origin coverage

### 6.1 Derived Region

An output Region is derived when a positive Derivation Assertion connects it to one or more contributing input Regions.

### 6.2 Transform-generated Region

A Transform-generated Region is content introduced by the Transform without attribution to upstream representation content.

Examples may include:

- a separator inserted by concat;
- fixed punctuation;
- a constant wrapper;
- other explicitly identified transform-introduced representation.

Transform-generated content must not be silently attributed to source inputs.

If provenance of a template or other content-bearing constant matters, representing that template/constant as an Artifact input provides stronger provenance than treating it as anonymous transform-generated content.

### 6.3 Unknown-origin Region

An output Region has unknown recorded origin when Part B cannot account for it through a positive Derivation Assertion or an explicit transform-generated classification.

Unknown-origin output prevents exact origin accounting for any containing scope.

### 6.4 Complete origin coverage

Complete origin coverage for an output scope means every portion of that scope is accounted for as either:

- exactly derived from explicit input scope(s); or
- explicitly transform-generated.

Complete origin coverage is a recorded provenance property, not proof that instrumentation captured every real contributor.

## 7. Direct versus transitive lineage

### 7.1 Direct derivation

Direct Derivation binds one generated output to input(s) of its generating Transform.

### 7.2 Recorded ancestry path

If:

~~~text
B directly derives from A
C directly derives from B
~~~

a verifier can report that A appears on a recorded ancestry path to C.

This does not automatically create a new direct Derivation Assertion from A to C.

### 7.3 Precision composition

Exact transitive Region mapping can be reported only when all intermediate mappings required for the composed path are exact and coordinate-compatible.

If any required intermediate derivation is partial, the composed derivation is at most partial.

If an essential intermediate contribution is unknown, an exact or positive composed derivation through that unknown step cannot be claimed.

## 8. Operation-specific semantics

## 8.1 Extract

Typical topology:

~~~text
input → Transform(extract) → output
~~~

If exact source and output Regions are known, extraction can record exact derivation for those Regions.

If the extracted content is known to come from the input but exact source location is unavailable, derivation is partial.

Parser configuration used only to choose fields or parsing behavior is control use unless its representation itself contributes output content.

## 8.2 Split

Typical topology:

~~~text
input
 ↓
split
 ├→ output 1
 ├→ output 2
 └→ output 3
~~~

Each output can map independently to one or more input Regions.

Dropped delimiters do not derive into outputs merely because the splitter inspected them.

If delimiters are copied into chunks, those copied Regions need their own mapping.

## 8.3 Chunk

Chunking is one-to-many and can legitimately produce overlapping Region mappings.

Example:

~~~text
source: ABCDEFG

chunk 1: ABCD
chunk 2: CDEF
chunk 3: EFG
~~~

The same source Region can therefore appear in multiple output derivations.

Overlap is not duplication of source identity; it is multiple lineage use of the same recorded representation Region.

## 8.4 Filter

Two cases are distinct.

**Artifact selection**

A filter can inspect candidate Artifacts and select a subset without creating new representations.

In this case selected existing Artifacts retain their identities. Excluded candidate Artifacts do not become ancestors of selected content merely because they influenced the filter decision.

**Within-artifact filtering**

If a filter creates a new Artifact by removing parts of an input representation, retained output Regions can derive from retained input Regions.

Removed input Regions do not derive into the output representation, although they may have affected control decisions.

## 8.5 Rerank

Rerank normally changes selection or ordering, not the representations of candidate Artifacts.

Candidate Artifacts can be used for scoring/control without becoming representation ancestors of one another.

A reranker can select/forward existing Artifacts in a new order.

If the implementation creates a ranking-list Artifact, that list is a new representation with its own provenance; it is not the same representation as the candidate text.

If ranked candidates are later concatenated, text derivation occurs in that later concat Transform from the selected candidate Artifacts.

## 8.6 Truncate

A truncation Transform generates an output whose retained Regions derive from retained input Regions.

Discarded input Regions do not contribute output representation content.

A length limit, token budget, or truncation policy is control metadata/input unless its representation is emitted into the output.

If truncation boundary mapping is not known precisely, derivation can be partial rather than exact.

## 8.7 Concat

Concat is normally many-to-one.

Example:

~~~text
A ─┐
B ─┼→ concat → O
C ─┘
~~~

Each contributed input Region can map to a distinct output Region.

Separators introduced between inputs are transform-generated unless represented as explicit Artifact inputs.

Exact origin coverage for the whole output requires the contributed Regions and separators/other introduced content to be fully accounted for.

## 8.8 Template

Template construction is many-to-one.

Inserted values derive from their corresponding input Artifacts/Regions.

Static template text is either:

- derived from a template Artifact input; or
- explicitly transform-generated.

A Producer cannot attribute static template text to an interpolated source value merely because both appear in the same generated output.

## 8.9 Normalize

Normalization can be one-to-one while changing length and byte representation.

Examples include:

- Unicode normalization;
- newline normalization;
- case normalization;
- whitespace normalization.

Whole-artifact ancestry can be exact even when byte equality is false.

Fine-grained Region mapping is exact only when the recorded mapping/profile supports the coordinate changes.

Otherwise the derivation can remain exact at whole-artifact scope while finer range lineage is partial or unavailable.

## 8.10 Redact

Redaction can preserve precise source ancestry without preserving source text.

For retained text, output Regions can map to retained input Regions.

For replacement content such as:

~~~text
[REDACTED]
~~~

the output replacement Region can be recorded as derived through the redaction Transform from the redacted input Region when the Producer intends to preserve ancestry of the replacement.

This does not mean the replacement bytes equal the redacted bytes.

Alternatively, privacy requirements can intentionally reduce mapping precision, yielding partial derivation.

Range metadata itself can be sensitive; Part B allows precision to be reduced rather than fabricated.

## 9. Control-flow influence without content contribution

A central false-provenance case is:

~~~text
input affected control flow
but contributed no output representation content
~~~

Examples:

- an excluded candidate changed the top-k ranking threshold;
- a policy file selected a branch;
- a token budget determined a truncation boundary;
- a score changed ordering;
- a feature flag selected a template;
- a negative match caused content to be omitted.

These relationships are usage/control provenance, not positive representation Derivation.

A verifier can report:

> Artifact X was recorded as a control input to Transform T.

It cannot upgrade that statement to:

> output Y was derived from X.

If the same input is both control-relevant and representation-contributing, usage role is mixed and positive Derivation Assertions identify the actual contributing scope(s).

## 10. Derivation claim matrix

| Claim | Evidence basis | Interpretation |
|---|---|---|
| Transform T used Artifact A | STRUCTURAL + PRODUCER_ASSERTED occurrence premise | Recorded use relation |
| A was control-only input to T | PRODUCER_ASSERTED | Control role assertion; not content derivation |
| T generated Artifact B | STRUCTURAL + PRODUCER_ASSERTED occurrence premise | Recorded generation relation |
| T selected existing Artifact A | STRUCTURAL + PRODUCER_ASSERTED occurrence premise | Selection/forwarding; no new Artifact identity |
| Derivation D links output B to inputs A,C through T | STRUCTURAL + PRODUCER_ASSERTED | Positive direct ancestry assertion |
| Derivation precision is exact | PRODUCER_ASSERTED; optionally REPRESENTATION-verifiable under a profile | Complete recorded origin accounting at asserted granularity |
| Derivation precision is partial | PRODUCER_ASSERTED | Positive ancestry, incomplete accounting |
| No Derivation Assertion exists | STRUCTURAL absence only | Does not prove no real derivation occurred |
| Compatible copy mapping verifies | REPRESENTATION | Region equality/mapping under applicable profile |
| A is on recorded ancestry path to C | STRUCTURAL graph reachability | Transitive recorded ancestry path |
| A directly derived C | unsupported from reachability alone | Requires direct Derivation Assertion |
| A caused model behavior | PROHIBITED_INFERENCE | Outside derivation semantics |

## 11. Normative requirements

### DRV-001 — Use does not imply derivation

A verifier MUST NOT infer a Derivation Assertion solely from a Transform use relation and generation relation.

Planned test: `derivation-use-generation-no-inference-001`.

### DRV-002 — Direct derivation binds one Transform

Every direct Derivation Assertion MUST identify exactly one generating Transform.

Planned test: `derivation-transform-cardinality-001`.

### DRV-003 — One target output

Every direct Derivation Assertion MUST target exactly one generated output Artifact, optionally narrowed to one output Region.

Planned test: `derivation-output-cardinality-001`.

### DRV-004 — One or more contributors

Every positive direct Derivation Assertion MUST identify one or more contributing input Artifacts, optionally narrowed to input Regions.

Planned test: `derivation-input-cardinality-001`.

### DRV-005 — Contributors are used inputs

Every input Artifact identified as a contributor in a direct Derivation Assertion MUST also be recorded as used by the identified generating Transform.

Planned test: `derivation-contributor-use-001`.

### DRV-006 — Target is generated by Transform

The output Artifact targeted by a direct Derivation Assertion MUST be recorded as generated by the identified Transform.

Planned test: `derivation-target-generation-001`.

### DRV-007 — Binary derived_from is shorthand only

A verifier MUST NOT interpret a binary derived_from rendering as stronger than the equivalent one-input qualified Derivation Assertion.

Planned test: `derivation-binary-shorthand-001`.

### DRV-008 — Exact derivation origin accounting

A Derivation Assertion labeled exact MUST provide complete recorded origin accounting for its claimed output scope: all representation-contributing input scopes are identified, required Region mappings are explicit at the asserted granularity, and any non-derived output portions are explicitly classified as transform-generated.

Planned test: `derivation-exact-coverage-001`.

### DRV-009 — Partial is positive ancestry

A Derivation Assertion labeled partial MUST identify at least one positive contributing input Artifact; partial MUST NOT be used as a synonym for unknown contribution.

Planned test: `derivation-partial-positive-001`.

### DRV-010 — Unknown is not a positive Derivation

When contribution cannot be established, a Producer MUST NOT create a positive Derivation Assertion merely to encode uncertainty.

Planned test: `derivation-unknown-no-edge-001`.

### DRV-011 — Usage role does not establish contribution

The usage roles data, control, mixed, and unknown MUST NOT by themselves be treated as positive Derivation Assertions.

Planned test: `derivation-use-role-no-edge-001`.

### DRV-012 — Control-only does not derive content

A verifier MUST NOT infer output representation derivation from an input solely because that input is recorded with control usage role.

Planned test: `derivation-control-no-content-001`.

### DRV-013 — Selection preserves Artifact identity

When a Transform only selects or forwards an existing Artifact without creating a new representation, a conforming record MUST preserve that Artifact identity rather than represent the selection as generation of the same Artifact.

Planned test: `transform-selection-identity-001`.

### DRV-014 — Selection does not imply derivation between candidates

A verifier MUST NOT infer Derivation among selected and excluded candidate Artifacts solely from filtering, ranking, routing, or selection activity.

Planned test: `transform-selection-no-derivation-001`.

### DRV-015 — New aggregate is a new Artifact

If a filtering, ranking, or routing operation creates a new wrapper, list, manifest, or aggregate representation, that representation MUST have a distinct Artifact identity from the selected member Artifacts.

Planned test: `transform-aggregate-identity-001`.

### DRV-016 — Region basis is explicit

Every Region used in a normative Derivation mapping MUST identify its Artifact and an applicable representation basis plus selector/coordinate scheme.

Planned test: `derivation-region-basis-001`.

### DRV-017 — No silent coordinate conversion

A verifier MUST NOT translate or compare Region coordinates across different representation bases or selector schemes unless the applicable profile defines that conversion.

Planned test: `derivation-coordinate-conversion-001`.

### DRV-018 — One-to-many is target-specific

For a one-to-many Transform, derivation knowledge for one generated output MUST NOT be copied automatically to another generated output.

Planned test: `derivation-one-to-many-isolation-001`.

### DRV-019 — Many-to-one preserves contributor set

For an exact many-to-one Derivation Assertion, all recorded representation-contributing input scopes for the claimed output scope MUST be represented in the same qualified assertion or an equivalent profile-defined contributor set.

Planned test: `derivation-many-to-one-contributors-001`.

### DRV-020 — Transform-generated content is not source-derived

A verifier MUST NOT attribute a Region explicitly classified as transform-generated to an upstream input Artifact without a separate positive Derivation Assertion.

Planned test: `derivation-generated-region-no-source-001`.

### DRV-021 — Unknown-origin blocks exact coverage

A verifier MUST NOT report complete exact origin coverage for an output scope containing any Region whose recorded origin is unknown.

Planned test: `derivation-unknown-region-blocks-exact-001`.

### DRV-022 — Missing edge is not non-derivation proof

The absence of a Derivation Assertion MUST NOT be reported as proof that no real representation derivation occurred.

Planned test: `derivation-absence-not-negation-001`.

### DRV-023 — Transitive reachability is not direct derivation

A verifier MUST NOT report a transitive ancestry path as a direct Derivation Assertion unless a direct Derivation Assertion is separately present.

Planned test: `derivation-transitive-not-direct-001`.

### DRV-024 — Exact mapping composition

A verifier MUST NOT report an exact transitive Region mapping unless every required intermediate derivation mapping is exact and coordinate-compatible under applicable profiles.

Planned test: `derivation-exact-composition-001`.

### DRV-025 — Partial degrades composed precision

If a required intermediate derivation on a composed ancestry path is partial, the verifier MUST NOT report the composed mapping as exact.

Planned test: `derivation-partial-composition-001`.

### DRV-026 — Unknown breaks positive composition

If an essential intermediate representation contribution is unknown, a verifier MUST NOT report a positive composed Derivation through that step solely from surrounding lineage edges.

Planned test: `derivation-unknown-composition-001`.

### DRV-027 — Concat separator accounting

An exact whole-output concat derivation MUST account for inserted separators or other transform-introduced Regions as transform-generated or as derivation from explicit Artifact inputs.

Planned test: `derivation-concat-separator-001`.

### DRV-028 — Template static-content accounting

A verifier MUST NOT attribute static template content to interpolated value Artifacts solely because they occur in the same generated output.

Planned test: `derivation-template-static-content-001`.

### DRV-029 — Truncation excludes discarded content derivation

A verifier MUST NOT infer that discarded input Regions contribute representation content to the truncated output solely because the truncation Transform inspected or measured them.

Planned test: `derivation-truncate-discarded-001`.

### DRV-030 — Rerank excluded-candidate rule

A verifier MUST NOT infer that an excluded or merely score-affecting candidate contributes representation content to downstream selected content solely because it participated in reranking.

Planned test: `derivation-rerank-control-001`.

### DRV-031 — Redaction is not byte equality

A verifier MUST NOT report a redaction replacement Region as byte-equal to its source Region merely because a Derivation mapping connects them.

Planned test: `derivation-redaction-no-equality-001`.

### DRV-032 — Precision reduction over fabrication

When privacy or instrumentation limitations prevent exact Region lineage, a Producer MUST use partial or unknown derivation semantics as applicable and MUST NOT fabricate exact Region mappings.

Planned test: `derivation-no-fabricated-range-001`.

## 12. Adversarial architecture review

### Review A — Control file chooses branch but contributes no text

~~~text
policy.json
   ↓ control
Transform
   ↓
output text from document A
~~~

The policy file is a control input, not a representation contributor.

No Derivation from policy.json to output text is created solely because it chose the branch.

Result: RESOLVED by DRV-011 and DRV-012.

### Review B — Excluded candidate changes ranking outcome

Candidate B can affect the score/order that causes Candidate A to be selected.

B is on the Transform's usage/control history but does not thereby become an ancestor of A's text or the later concatenated text.

Result: RESOLVED by DRV-014 and DRV-030.

### Review C — One input split into overlapping chunks

One source Region can map to several outputs, including overlapping chunk ranges.

Each output has target-specific derivation.

Result: RESOLVED by DRV-018 and Region semantics.

### Review D — Many inputs jointly generate one value

~~~text
A ─┐
B ─┼→ compute → O
C ─┘
~~~

Binary edges lose the contributor-set grouping for joint origin accounting.

Qualified n-ary Derivation preserves that contributor set.

Result: RESOLVED by DRV-019.

### Review E — Concat inserts newlines

~~~text
A + "\n" + B
~~~

The newline is not source-derived from A or B.

Exact whole-output origin coverage requires it to be transform-generated or represented as an explicit Artifact input.

Result: RESOLVED by DRV-020 and DRV-027.

### Review F — Template static prefix

~~~text
"Context: " + value
~~~

The prefix does not derive from value.

Result: RESOLVED by DRV-028.

### Review G — Unicode normalization changes offsets

An exact whole-artifact ancestry claim can survive normalization while byte-level Region offsets change.

Fine-grained exact mapping requires an explicit compatible mapping/profile.

Result: RESOLVED by DRV-016, DRV-017, and DRV-024.

### Review H — Redaction placeholder

~~~text
secret@example.com
→
[REDACTED]
~~~

The replacement can preserve positive ancestry from the redacted source Region without implying byte equality.

If privacy policy suppresses exact source position, derivation precision can be reduced.

Result: RESOLVED by DRV-031 and DRV-032.

### Review I — Filter passes Artifact unchanged

If filter chooses Artifact A unchanged, it selects/forwards A instead of generating "A2" solely to represent selection.

If the system intentionally creates a new wrapper or copy representation, that new representation receives its own Artifact identity and applicable derivation.

Result: RESOLVED by DRV-013 and DRV-015.

### Review J — Used input with unknown contribution

Instrumentation knows that T read A and generated B but cannot determine whether A contributed B's content.

The record retains the use with role unknown/data as justified and emits no positive Derivation solely from co-occurrence.

Result: RESOLVED by DRV-001 and DRV-010.

### Review K — Multi-stage exact + partial

~~~text
A --exact→ B --partial→ C
~~~

A verifier can report a recorded ancestry path A→B→C, but the A→C composed mapping is not exact.

Result: RESOLVED by DRV-023 through DRV-025.

### Review L — Exact + unknown gap + exact

~~~text
A --exact→ B
B ?→ C
C --exact→ D
~~~

Surrounding exact edges do not bridge the unknown contribution step into a positive exact A→D derivation.

Result: RESOLVED by DRV-026.

### Review M — Filter removes a source span after inspecting it

An input span can affect a predicate but be absent from output content.

Inspection/control influence does not create output representation derivation for that removed span.

Result: RESOLVED by DRV-012.

### Review N — Same bytes regenerated from constant

Transform generates "OK" while an input Artifact also contains "OK".

String equality alone does not prove Derivation.

The output can be transform-generated even though bytes happen to match input bytes.

Result: RESOLVED by DRV-001 and DRV-020.

### Review O — Hash-only inputs

Input content may be unavailable while ancestry is Producer-asserted.

The Derivation can remain partial/asserted, but a verifier cannot upgrade it to representation-verified exact mapping without the necessary evidence.

Result: RESOLVED under Phase 0 evidence-basis rules and DRV-032.

### Review P — Summary or lossy semantic transform

A deterministic or model-based summarizer can use source artifacts and generate output whose exact source ranges are not defensible.

The Producer can record positive partial ancestry if contribution is known, or unknown derivation if even contribution cannot be established.

Part B does not invent token-level or semantic attribution.

Result: RESOLVED by exact/partial/unknown separation.

### Review Q — Duplicate input used twice in concat

The same Artifact or Region can be intentionally inserted more than once into an output.

The mappings are separate output Region mappings, not new source identities.

Result: RESOLVED.

### Review R — Transform reads a secret only to decide whether to emit fixed warning text

The secret affects control flow; the fixed warning is transform-generated.

Unless the Producer intentionally makes a positive ancestry assertion under a defined policy, core v0.1 does not convert control dependence into representation Derivation.

Result: RESOLVED by DRV-012 and DRV-020.

## 13. Architecture revisions caused by Part B

Part B makes two explicit refinements to Phase 0.

### 13.1 Derivation is qualified and n-ary on inputs

Phase 0's binary:

~~~text
output derived_from input
~~~

is retained only as display shorthand.

The semantic form is:

~~~text
Derivation Assertion
  generating Transform: T
  target output: O [optional Region]
  contributors:
    - A [optional Region]
    - B [optional Region]
    - ...
  precision:
    exact | partial
~~~

Unknown derivation is not represented as a positive Derivation Assertion.

### 13.2 Selection / forwarding is distinct from generation

Phase 0's Transform semantics are refined so that an Activity can:

~~~text
use existing Artifact
select / forward existing Artifact
generate new Artifact
~~~

Selection does not manufacture a new Artifact identity.

This is essential for filter and rerank semantics.

## 14. Part B resolved decisions

Part B locks the following decisions:

1. Transform use/generation does not imply Derivation.
2. Derivation is a qualified direct Assertion tied to one generating Transform and one target output.
3. Many-to-one joint contribution uses an n-ary contributor set.
4. One-to-many derivation knowledge is target-specific.
5. Exact derivation means complete recorded origin accounting at the claimed granularity, not byte equality or causality.
6. Partial derivation is positive but incomplete ancestry.
7. Unknown derivation is a knowledge state and does not create a positive Derivation edge.
8. Region mappings are relative to explicit Artifact representation bases and selector schemes.
9. Selection/forwarding preserves existing Artifact identity.
10. Filter/rerank control influence is not representation Derivation.
11. Transform-generated content is distinct from source-derived content.
12. Exact transitive Region mappings require exact, compatible intermediate mappings.
13. Partial or unknown intermediate lineage prevents exact transitive mapping.
14. Extract/split/chunk/filter/rerank/truncate/concat/template/normalize/redact all fit the model without special causal claims.
